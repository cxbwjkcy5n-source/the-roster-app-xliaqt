================================================================================
AUTHENTICATION FLOW
================================================================================

WEB:
1. User clicks Google/Apple/GitHub login
2. Opens popup window with /auth-popup?provider=google
3. Popup redirects to backend OAuth endpoint
4. Backend redirects to /auth-callback with token
5. Callback extracts token and sends to parent window
6. Parent window stores token and fetches user session
7. Popup closes automatically

NATIVE:
1. User clicks Google/Apple/GitHub login
2. Opens OAuth provider in browser
3. Backend handles OAuth flow
4. Redirects back to app via deep link (theroster://)
5. BetterAuth handles token storage
6. App fetches user session

EMAIL/PASSWORD:
1. User enters credentials
2. Calls authClient.signIn.email() or authClient.signUp.email()
3. BetterAuth handles authentication
4. Token stored automatically
5. App redirects to roster screen

NOTES
================================================================================

1. Image upload endpoint exists but not fully implemented
   - Currently stores local URI
   - Production would need multipart/form-data upload

2. All endpoints require authentication except /api/auth/*
   - Bearer token automatically added by authenticatedGet/Post/etc.
   - Token stored in SecureStore (native) or localStorage (web)

3. Backend URL configured in app.json
   - Never hardcoded in code
   - Always read from Constants.expoConfig?.extra?.backendUrl

4. BetterAuth handles all authentication
   - Session management
   - Token storage
   - OAuth flows
   - Deep linking

5. RosterContext is the single source of truth
   - All components use useRoster() hook
   - No direct API calls from components
   - Consistent error handling
